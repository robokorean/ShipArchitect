# v0.9.4 구현·검증 범위

2026-11-24 KST. PR #2의 `dev/v0.9.4`, 기준 `2bad0300`의 기존 545개 검증 기능을 유지하며 남은 시설 설계·실함 검증·정식 패키징을 마무리했다. 공간 인식 알고리즘을 재작성하지 않았다.

## 구현

- 기본 작업 순서, 선택 대상 작업, 다음 단계, 기본/고급 작업공간 및 통합 변경 검토. 기존 리본·공간·설비·경로·2D/3D·편집·진단은 유지한다.
- 사용자 확인 시설의 확정 공간·내부 후보를 정확한 희소 run 합집합으로 설계한다. 원래 ID·물리적 경계·확정 상태는 바꾸지 않는다. 시설 밖과 구성 공간 사이 틈은 배치 권한이 아니다.
- 사라진 구성원·외부/제외/불완전 후보는 차단한다. 미확정 구성원 수와 시설·설비·정적 경로 근거를 AI에 전달한다. 시설 용도·장치 동작·게임 충돌을 자동 확정하지 않는다.
- JSON/재료 수정, 대화 재실행, 승인·저장 후 Undo/Redo에도 같은 시설 범위를 유지한다. 선택 변경 시 이전 승인을 해제한다. 재료 재검증도 내부 경로 보호를 유지한다.
- 실제 한국어 요청에서 ‘천장은 추가하지 마’를 재료로 오해하고 ‘통로’를 ‘통’ 블록으로 오해하던 두 파서를 수정했다. 알 수 없는 실제 재료 이름은 계속 오류 처리한다.

## 수행한 검사

- 로컬 Linux: 전체 **552개 통과** (100.18초, 실제 모델 추론 동시 수행 환경). 기존 545개 + 시설 5개 + 한국어 재료 2개. 문법·회귀·Qt offscreen GUI 포함. CI는 동일 소스의 Linux/Windows 전체 테스트와 독립 실행을 수행한다. 원격 결과는 해당 커밋의 Actions를 기준으로 한다.
- 실제 `ship_f(1).schem`의 새 분석: 1,974개 후보, 622,429셀, 검토 257개/479,929셀. 기존 `recognition(4).json`과 모든 후보 ID·복셀 run·지문·판정이 동일했다. 원본 입력 파일과 블록·NBT는 불변이다.
- `design.shipproj`: 확정 공간 129개·형상·ID, BlockEntity 11,227개와 NBT를 저장/재열기에서 보존했다. 실제 AI 승인·저장 검사에서도 기존 Undo 66개가 그대로 앞부분에 남았다. 분석 및 프로젝트 왕복 전체 측정 55.76초는 인식 단독 벤치마크가 아니다.
- 실제 Ollama **0.40.18 / qwen3:4b**, Linux CPU: 실함의 두 확정 공간을 검증용 논리 시설로 묶고 한국어로 유리 1개씩을 요청했다. 1회 응답, 238.24초, 입력 4,429/출력 299토큰. 정확히 두 구성 공간에 2개 변경을 제안했다. 승인 전 블록 불변, UI 승인 → Undo/Redo → 프로젝트 왕복 → `.schem` 내보내기/재열기, 원본 파일 불변과 NBT 보존을 확인했다. 두 블록 검증은 일반적인 대규모 인테리어 품질 검증을 뜻하지 않는다.
- 자동 테스트의 Ollama 시나리오는 HTTP 모의 서버로 오류·취소·범위·보호·재실행을 재현한다. 위 실제 모델 검사는 별도이며 모의 응답을 실제 추론으로 표기하지 않는다.
- 배포는 허용 목록으로 최신 실행 파일 **82개**만 만든다. 독립 실행 검사는 개발 `src`를 실제로 격리하고 새 한글·공백 폴더와 별도 의존성 캐시에서 실행한다. Windows cmd/pythonw, 실제 Qt 3D 프레임·블록 배치·프로젝트/스키매틱 왕복·NBT·진단 내보내기를 자동 확인한다.

## 남은 검증·제한

사용자 Windows 11·RTX 3060에서 v0.9.4의 실제 조작감·기본 화면의 클릭/용어/패널 가림, 듀얼 모니터·V3·실제 Qwen3 속도는 미검증이다. Windows CI offscreen은 이 실사용 검증을 대신하지 않는다. 시설 생성/해제/Undo의 사용자 확인도 아직 필요하다.

AI는 제한된 구조화 연산으로 설계안을 만든다. 모든 시설의 용도·미완성 구조를 정확히 해석하거나 복잡한 대형 인테리어를 완성한다는 보장은 없다. 큰 문맥은 제한/표본화되며 Python이 실제 셀과 블록을 최종 검사한다. 설비 목록은 저장된 분석 기록이며 기록 부재가 설비 부재를 뜻하지 않는다. 미확정 이동 경로는 보존하지만 Minecraft의 실제 충돌과 장치 동작은 별도 확인이 필요하다.

실함 원본·개인 프로젝트·개인 진단·실제 모델 상세 응답/이미지는 공개 저장소나 실행 ZIP에 넣지 않는다. 개발 증거는 별도 보관한다. Windows 실사용 순서는 `docs/V094_TEST_GUIDE.md`를 따른다.
