# Development

Runtime packages are produced only by tools/build_release.py from an explicit allowlist. Tests, tools, private inputs, logs, older archives and verification reports never enter the runtime ZIP.

Run python -m pip install -r requirements-dev.txt then python -m pytest -q. Use QT_QPA_PLATFORM=offscreen for automated Qt tests.

Private ship projects, schematics, diagnostics and screenshots must never be committed. Synthetic fixtures are generated by tools/create_v0931_demo.py. Real-file test results are retained separately.

The original legacy ZIP remains preserved outside Git. Imported v0.9.3.1 runtime and test source provides a baseline commit; v0.9.3.2 records the functional changes.

## v0.9.3.2 verification

Linux/Python 3.12: 451 automated tests passed. Qt uses the offscreen platform;
this does not certify Windows graphics drivers, physical multi-monitor behaviour,
or a live Ollama model. The connection tests use a controlled local HTTP server.
The complete ship mesh is retained during interaction; complex space fills are
deferred until release. Exterior recognition remains experimental: ambiguous
openings and merged components require review rather than automatic registration.

## v0.9.3.3 exterior recognition

The exterior flood and erosion/expansion passes stay in place. Terrain masking
is analysis-only and requires a broad, thin bottom soil component connected
to the schematic's lateral edge. Original solid cells are never candidates.
Proposed partition repairs compare real horizontal air-to-air faces, floor
and roof levels, aperture dimensions and passage blocks. A protected or
rejected source fingerprint prevents repair. Competing repairs remain under
review. Labels are geometry hypotheses rather than game collision or room-use
ground truth. Coordinate samples and face counts explain the distinction.

Use the existing connectivity method as a control. A large exterior-connected
multi-deck component can still remain unresolved after the second core pass.
Partial selections may provide insufficient terrain or opening evidence.
Private schematics, OBJ exports and coordinate-level comparisons are retained
outside this repository.

Verification: Linux Qt offscreen passed 460 tests, including 9 new structure
and UI cases. The release workflow repeats the full suite and the extracted
distribution check on Windows.

## v0.9.3.4 analysis snapshots

Raw schematic identity combines its resolved path and original bytes; sidecar
spaces are stored as spaces-{project_id}.json in the app data directory.
Matching geometry history, revision, ID and size are checked when restoring.
Project archives embed spaces and recognition state in project.json; opening
does not run recognition. Compatible newer sidecar metadata is recovered
with Undo. Older metadata retains its original provenance.

Clean analysis uses the current committed voxel array through a fresh
analysis context without prior candidates, decisions or cache. Protected
analysis applies existing rules. Both stage candidates in the project; only
explicit candidate registration updates confirmed spaces. Comparison uses
per-row interval intersections and preserves the previous snapshot.
Block signatures prevent registering a stale versioned result.

Broad exterior-connected complexes are divided only where physical
deck contact exists on both sides. Residual open vertical connections
remain diagnostic samples; derived parts stay hidden and unregistrable.
The method does not identify the purpose of an upper or lower installation.

The previous test for JSON export now checks the current package version
instead of a hard-coded 0.9.3.3. Its geometry and export assertions remain.
