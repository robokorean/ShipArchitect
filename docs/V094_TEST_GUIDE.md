# v0.9.4 검증 범위와 Windows 실사용 점검

자동 테스트의 GUI 검사는 Qt offscreen 환경입니다. 실제 모니터에서의 가독성·조작감·V3 검사는 대신하지 않습니다. 원본을 보존하고 복사 프로젝트를 사용하세요.

| 클릭 순서 | 합격 기준 |
|---|---|
| 새 폴더 압축 해제 → START_WINDOWS.cmd → 열기 → 프로젝트 열기 | 기존 공간·이력이 복원되고 중앙 함선이 보임 |
| 공간 분석 → 탐색기 공간 선택 → 선택·수정 | 다음 단계와 해당 대상의 속성이 보이고 기존 기능에 접근 가능 |
| Ctrl/Shift로 두 확정 공간 선택 → 선택 대상 작업 → 시설로 묶기 → 저장 | 원래 공간 ID·경계를 유지한 시설이 나타남. 용도는 사용자가 확인한 값만 입력 |
| 시설 노드 선택 → AI 내부 설계 → 연결·사용 재료 설정 | Ollama 연결 상태와 qwen3:4b 모델을 확인. 역할 재료는 요청문 해석을 원하면 빈칸으로 유지 |
| ‘두 구성 공간에 유리 장식을 제안하고 기존 벽·장치·통로는 유지’ → 설계안 생성 | 실제 변경 수·재료·범위가 표시되고 승인 전 원본 블록은 그대로임. 0개/오류는 완료 처리하지 않음 |
| 변경 검토 → 변경 전 보기 / 변경 후 보기 | 정확한 셀 합집합 안에만 변경되고 공간 사이 빈틈·외부·보호 장치는 그대로임 |
| 설계 명령 상세 수정 → 수정한 설계 검증·미리보기 | 이전 승인이 해제되고 다시 검증됨. 기존 경로 보존 구간 충돌은 차단됨 |
| 다른 공간 선택 | 이전 시설 설계 미리보기 승인이 해제됨 |
| 확인한 변경 승인·적용 → Ctrl+Z → Ctrl+Y → 저장 → 재열기 | 변경·복구·재적용이 일치하고 공간·NBT·기존 이력을 유지 |
| 더 보기 → 모든 기능 검색 / 고급 작업공간 | 기존 공간·설비·경로·수동 편집 기능에 접근 가능 |
| 더 보기 → 오류 진단 ZIP | 실패 원인·작업 ID가 포함된 ZIP 생성 |

시설 전체 설계가 경계 상자 전체 건축을 뜻하지 않습니다. 구성 공간의 정확한 셀만 사용하며, 외부·제외·불완전 후보 또는 누락된 구성원이 있으면 먼저 검토해야 합니다. 시설 그룹 해제는 공간 삭제와 다릅니다.

남은 실사용 점검: Windows 11·RTX 3060의 실제 Qwen3 응답 시간, 복잡한 격납고 시설의 장식/배치 품질, 기본 화면 클릭 경로와 용어 혼동, 듀얼 모니터·도킹, V3 반복 검사, 실제 Minecraft 충돌 및 모드 장치 동작. 사용자 확인 전에는 완료로 기록하지 않습니다.
